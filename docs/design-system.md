# 设计基础规范

本规范把 Arco Design 的原则转为本项目可直接执行的规则。新产品页面默认遵守；需要偏离时，必须在需求或代码评审中说明原因。

## 设计目标

后台页面首先服务于高频、准确、可恢复的任务完成：

| 原则 | 本项目执行方式 |
| --- | --- |
| 及时反馈 | 请求有加载态，提交有按钮 loading，完成后给出具体结果 |
| 贴近现实 | 使用业务人员熟悉的名称，不展示接口字段名或错误代码代替解释 |
| 系统一致 | 同类页面采用同一页面模式、组件、文案和操作位置 |
| 防止错误 | 必填前置校验；破坏性操作确认；提交期间阻止重复点击 |
| 突出重点 | 一个操作区只保留一个主按钮，次要信息降低层级 |
| 错误帮助 | 说明发生了什么、影响什么、用户下一步能做什么 |
| 易于恢复 | 搜索失败保留条件，提交失败保留输入，页面错误提供重试 |

## 颜色与主题

SaiAdmin 支持动态主色、浅色/深色模式和多套皮肤。设计稿中的某个十六进制颜色不能被当成固定实现值。

### 颜色使用表

| 用途 | 使用方式 | 禁止做法 |
| --- | --- | --- |
| 主操作、选中、链接 | `rgb(var(--primary-6))` 或 Arco 组件的 `type="primary"` | 硬编码 Arco 默认蓝 `#165DFF` 或当前默认紫色 `#7166F0` |
| 主/常规/次要/禁用文字 | `var(--color-text-1)` 至 `var(--color-text-4)` | 自定义一组灰色覆盖 Arco 文本层级 |
| 页面、卡片、浮层背景 | `var(--color-bg-1)` 至 `var(--color-bg-5)`，沿用当前容器层级 | 直接写 `#fff`、`#000` |
| 分割线和边框 | `var(--color-border-1)` 至 `var(--color-border-4)` | 为同一层级发明不同灰线 |
| 中性填充、悬停 | `var(--color-fill-1)` 至 `var(--color-fill-4)` | 用透明黑模拟所有状态 |
| 成功、警告、错误 | 优先使用 Arco 的 `status`、`Message`、`Alert`、`Result`、`Tag` 语义 | 只用颜色、不显示文字或图标含义 |

要求：

- 自定义样式必须同时检查浅色、深色和切换主色后的效果。
- 状态信息必须有文字，例如“启用”“停用”“审核失败”；不能只显示红点或绿色背景。
- 图表颜色用于区分系列，不替代图例、数值或状态文字。
- 图片、Logo 等品牌资产确需固定色时可以例外，但不能影响文本和操作的可读性。

## 字体与信息层级

使用 Arco 的系统无衬线字体栈，不在业务页面单独引入字体。一个页面控制在 3 至 5 个文字层级。

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 辅助文字 | `12px / 20px` | 400 | 帮助、时间、次要说明 |
| 正文 | `14px / 20px` | 400 | 表单、表格、说明正文 |
| 区块标题 | `16px / 24px` | 500 | 卡片、表单分组标题 |
| 页面标题 | `20px / 28px` | 500 或 600 | 独立页面主标题 |
| 关键指标 | `24px / 32px` | 600 | 仪表盘核心数值，不用于普通正文 |

- 最小字号为 `12px`；不能靠缩小字号塞入更多内容。
- 重要性优先通过层级、字重和留白表达，不连续使用多个高饱和颜色。
- 长段落采用至少 `1.5` 倍行高，段落之间保留不小于正文行高的间距。
- 表格数字需要比较时使用统一格式，并保持列内对齐。

## 间距、栅格与容器

组件内部微间距以 `4px` 为单位，页面布局以 `8px` 为基础节奏。只使用下面的间距序列：

`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48px`

常用规则：

- 桌面页面外边距和主要区块间距：`24px`。
- 小屏页面外边距和区块间距：`16px`。
- 卡片内容内边距：简单内容 `16px`，信息密集或分组内容 `24px`。
- 表单项、按钮组和卡片之间优先用 `a-space`、`a-row` 的 `gutter` 或上述序列，不使用随机数值。
- 标准业务内容放入 `.ma-content-block` 或 Arco `a-card`；同一视觉层级不要重复套卡片。

页面使用 Arco 24 栅格。当前 Arco Vue 2.57.0 的断点为：

| 断点 | 宽度 |
| --- | --- |
| `xs` | 小于 `576px` |
| `sm` | 大于等于 `576px` |
| `md` | 大于等于 `768px` |
| `lg` | 大于等于 `992px` |
| `xl` | 大于等于 `1200px` |
| `xxl` | 大于等于 `1600px` |

默认使用 `24px` 水槽；小屏可以降为 `16px`。内容必须对齐栅格列，不能落在水槽中。

## 圆角、边框与阴影

- 使用 Arco/SaiAdmin 的圆角变量；SaiAdmin 会通过设置切换 `--border-radius-small` 和 `--border-radius-medium`。
- 普通卡片依靠背景、边框和留白建立层级，不为每个区块增加阴影。
- 下拉、浮层、Modal、Drawer 使用 Arco 自带阴影，不在页面中自定义更高层级的阴影。
- 同一页面的卡片边框、圆角和阴影保持一致。

## 按钮与操作层级

| 场景 | 规则 |
| --- | --- |
| 主操作 | 每个操作区最多一个 `type="primary"`，例如“新建订单”或“保存” |
| 次操作 | 使用默认或 `secondary` 按钮，例如“导出”“重置” |
| 行内操作 | 使用 `a-link`，顺序为查看、编辑、其他、删除 |
| 破坏性操作 | 使用 `status="danger"`，并通过 `a-popconfirm` 或确认 Modal 说明影响 |
| 图标按钮 | 必须有 Tooltip，并提供可被辅助技术识别的名称 |

- 按钮文案优先“动词 + 名词”，避免“确定操作”“处理一下”等模糊表达。
- 表单默认使用 Arco `medium` 尺寸（控件高度 `32px`）；不要在同一表单混用多种高度。
- 请求中的按钮显示 loading 并阻止重复提交；不能只在请求完成后补一条消息。
- 没有权限的操作使用 `v-auth` 从界面移除；暂时不可用但需要被理解的操作才使用 disabled，并解释原因。

## 表单与数据录入

- 使用 `a-form`、`a-form-item`，每个可编辑字段都提供可见 label；placeholder 只能补充示例，不能替代 label。
- label 尽量控制在 6 个汉字以内；业务名称不能缩写时，以清楚为先。
- 必填、格式、长度和业务限制在提交前校验，错误信息放在对应字段附近。
- 长表单使用 `scroll-to-first-error`，校验失败后定位第一个错误字段。
- 有限选项使用选择器、单选或字典组件；日期、数值、层级等使用对应控件，不用普通输入框代替。
- 单列是默认布局。只有字段彼此独立、屏幕空间充足时才使用双列；有依赖关系的字段保持连续阅读顺序。
- 只读详情使用 `a-descriptions` 或正文展示，不用一组 disabled 输入框伪装详情。
- 打开新增/编辑表单时重置数据和校验；提交失败保留用户输入。

## Modal 与 Drawer

| 容器 | 推荐尺寸 | 使用场景 |
| --- | --- | --- |
| 确认 Modal | `400px` | 简短确认或警告 |
| 简单表单 Modal | `520px` | 少量、单区块字段 |
| 中型表单 Modal | `720px` | 需要更多字段但仍是单一任务 |
| Drawer | 桌面详情 `60%` 或常规编辑 `720px`，移动端 `100%` | 查看详情、不中断上下文的复杂编辑 |
| 独立页面 | 占满工作区 | 多区块、步骤化、需要横向空间或二次导航的任务 |

数据录入 Modal 必须设置 `:mask-closable="false"`、校验、提交 loading 和明确标题。正文超高时只让内容区纵向滚动，标题和操作区保持可见；禁止 Modal 正文横向滚动。

频繁的行内删除优先 `a-popconfirm`；复杂或不可逆后果才使用确认 Modal。不要叠加多个 Modal。关闭后不应保留上一次临时状态，必要时使用 `unmount-on-close`。

## 加载、空、错误与权限状态

每个异步页面都要设计完整状态：

| 状态 | 展示规则 | 推荐组件 |
| --- | --- | --- |
| 首次加载 | 保持容器高度稳定；表格使用内置 loading，卡片使用 Skeleton 或 Spin | `SaTable`、`a-skeleton`、`a-spin` |
| 局部提交 | loading 放在触发按钮或局部区域，不遮挡整个页面 | `a-button :loading`、`a-spin` |
| 无数据 | 说明没有什么数据；如果用户可行动，给出“新建”或“清空筛选” | `a-empty` |
| 搜索无结果 | 保留筛选条件并提供重置，不显示成系统错误 | `a-empty` + 重置按钮 |
| 页面错误 | 说明原因和恢复动作；可重试时显示“重新加载” | `a-result`、`a-alert` |
| 无权限 | 隐藏无权操作；整页不可访问时说明无权限并提供返回入口 | `v-auth`、`a-result status="403"` |
| 成功 | 说明具体结果，例如“订单保存成功”，随后刷新相关数据 | `Message.success` |

网络层的全局错误消息不能替代页面恢复入口。刷新失败时保留用户当前筛选、分页或已输入内容。

## 响应式规则

- CSS 布局优先使用 Arco Grid 和现有 Tailwind 响应式类。`tool.getDevice()` 只有触屏且宽度小于 `768px` 才返回 `mobile`，不能把它当作唯一布局断点。
- 搜索表单默认 `:xs="24" :sm="8"`；小屏单列，按钮组换行并保持主操作可见。
- Modal 和 Drawer 在移动端使用 `100%` 宽度；复杂任务在小屏仍难以完成时，改为独立页面而不是继续压缩。
- 表格可以在组件内部横向滚动，但整个工作区不能产生横向滚动。
- 移动端只保留识别对象和完成核心任务需要的列，其他信息进入详情 Drawer。
- 不把关键操作放在只有 hover 才能出现的位置。
- 桌面图标点击区域不小于 `32px`；触屏核心操作的点击区域建议不小于 `44px`。

## 无障碍与可理解性

- 使用 Arco 组件不等于自动满足无障碍标准，业务页面仍需单独验收。
- 键盘可以到达并操作所有按钮、链接、表单和弹层；焦点样式保持可见。
- 图标、颜色和位置都不能成为唯一信息来源。
- 图标按钮提供 Tooltip 和可识别名称；图片按用途提供替代文本，装饰图不重复朗读。
- 表单 label、校验错误和字段建立明确关联；错误不能只显示在顶部 Message。
- 表格列有清楚表头，选择、排序和展开状态可理解。
- 普通文字与背景对比度至少 `4.5:1`；大号文字、图标和控件边界至少 `3:1`。
- 重要异步结果除视觉反馈外，还要能被辅助技术感知；不能只依赖瞬时 Message。
- Modal/Drawer 打开后焦点进入弹层，关闭后返回触发元素。
- 使用 Arco 主题 token 保持对比度，不在 disabled 文本上承载关键说明。

## 文案与数据格式

- 同一对象在菜单、标题、按钮、字段和提示中使用同一个名称。
- 成功文案写具体结果：“保存成功”“删除成功”“状态已启用”；避免统一写“操作成功”。
- 错误文案包含原因和下一步：“文件超过 10 MB，请重新选择”。不要只展示 `404`、`500` 或堆栈。
- 空值统一显示 `—`，不要混用空字符串、`null`、“暂无”和短横线。
- 日期使用 `YYYY-MM-DD`，日期时间使用 `YYYY-MM-DD HH:mm:ss`，采用 24 小时制。
- 四位以上业务数值按场景使用千分位；单位放在列标题或数值后，并保持整列一致。
- 中文与英文、数字之间保留合理空格；按钮和标题不使用句号。

## 页面设计验收

交付前逐项确认：

- 只有一个清晰的主任务和主操作。
- 浅色、深色和更换主题色后仍清晰可用。
- 正常、加载、空、错误、权限和长内容状态完整。
- 桌面与小屏没有页面级横向滚动，核心操作无需 hover。
- 表单可校验、可恢复，提交不会重复触发。
- 破坏性操作说明对象和影响，并有确认机制。
- 文案具体、术语一致，空值和日期格式统一。
- 键盘主流程、`200%` 缩放和 `375px` 宽度下仍可完成核心任务。
